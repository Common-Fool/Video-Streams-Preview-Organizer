# VO SP (pairview.py)

Один файл `pairview.py` (~4200 строк, Python 3.8+, только стандартная библиотека; `pywebview` и `ffmpeg` — внешние, необязательные).
Программа для Windows (основная система владельца), работает и на macOS/Linux: галерея превью-листов («contact sheets» с таймкодами) к видео. Ходит по папке и подпапкам, связывает видео и превью по имени,
даёт парное удаление, групповые действия, создание недостающих превью через ffmpeg, запуск в выбранном видеоплеере (рекомендуем MPC-HC), открытие в проводнике.
Название — VO SP (Video Organizer: Streams Preview), константа `APP`; имена файлов сборки — `VO_SP` (до v1.4 — VSPO). Интерфейс — локальный веб-сервер + страница (HTML/CSS/JS лежат внутри строки `PAGE`). Открывается в собственном окне (pywebview/WebView2) или в браузере.

## Модель данных

- **Пара** — файлы с одинаковым именем без расширения в одной подпапке. Ключ `(normcase(относительная подпапка), имя.lower())`.
  `GROUPS[id] = {name, dir, key, v: [видеофайлы], p: [превью]}`, файл = `(путь, корень, размер, mtime)`.
- Видео — расширения из `VIDEO`; превью — из `IMAGE`. Имя `клип.mp4.jpg` считается превью к `клип`.
- **Игнор** (`IGNORE`, по умолчанию `.ts`, параметр `--ignore-ext`): такие файлы не видео, а превью к ним скрыты и не считаются «сиротами».
- Два корня: `VROOT` (видео) и `PROOT` (превью, параметр `--previews`; подпапки те же). Если не задан, `PROOT == VROOT`.
- `scan()` пропускает `_to_delete`, скрытые и системные папки (имена на `.`, `@`, `#` — например `@eaDir`, `#recycle`).
- Номера пар (`id`) не переиспользуются (`new_id()` учитывает и пары из стека отмены). Страница ссылается на пары только по `id`;
  пути с клиента не принимаются, кроме относительных папок, которые проверяет `inside_root()` (выход за корень запрещён).
- `rescan()` («Обновить», F5): новый обход и слияние с `GROUPS` по ключу, у прежних пар `id` сохраняются; пары, которыми сейчас занят ffmpeg, не трогаются.
- Блокировки: `POS_LOCK` — позиции просмотра (берётся внутри `LOCK`, не наоборот); `LOCK` (RLock) — `GROUPS` и `UNDO`; `ROOTLOCK` — смена папки и `rescan()`; `JLOCK` — `JOB`; `GLOCK` — `GPU`/`FAST`; `TLOCK` — счётчик корзины; `SLOCK` — файл настроек; `CLOCK` — `CUT` (порядок захвата: `LOCK` → `JLOCK` → `CLOCK`).

## Удаление, «корзина», отмена

- «Удалить» ничего не стирает: перенос в `<корень>\_to_delete\<та же подпапка>`. Насовсем — только `purge()` (кнопка «To delete» → «Delete permanently»).
  Из страницы очистка идёт в фоне (`purge_start()`, ход в `PURGE`, опрос `GET /api/purge`): по SMB тысячи файлов удаляются минутами —
  окно «To delete» сразу закрывается, ход — короткой строкой на кнопке `#trash` в шапке, итог — тостом (`purgeShow()`, `purgeSeen`).
  `--purge` в консоли зовёт `purge()` напрямую. Всплывающие окна шапки (`#trashp`, `#rootp`, `#menup`) клавиши не держат: Esc закрывает,
  любая другая клавиша закрывает окно и работает как обычно. Тост закрывается ✕ (`#toastx`), под мышью не исчезает.
  Размеры для окна удаления папки и счётчика корзины — `tree_files()` (scandir: в Windows размер приходит со списком папки, без запроса на файл).
  `purge()` трогает только папки с точным именем из `TRASH_NAMES` внутри корней и не ходит по ссылкам.
  `TRASH_NAMES` = `_to_delete` и прежнее имя `_на_удаление`: старая корзина тоже пропускается обходом, считается и очищается.
- Перенос — только `os.rename` (`move()`): никакого `shutil.move` (он молча копирует гигабайты). При `PermissionError` (файл занят плеером/рекордером/антивирусом)
  `move()` повторяет 6 раз с паузой 0,3 с, потом `MoveError`; `explain()` превращает ошибку в понятный текст. Сбой одного файла пары откатывает всю пару.
- `UNDO` — стек. Одна запись = одно действие = список `(gid, группа, [(откуда, куда)])`. `g is None` — перенос папки целиком (возвращается переименованием папки).
  Запись обрезки — 4 элемента: `(gid, снимок пары, [(оригинал, корзина), (старое превью, корзина)], [(обрезанный файл, корень), (новое превью, корень)])`:
  `undo_last()` сначала уносит в корзину файлы из 4-го элемента, потом возвращает оригиналы; пока идёт создание превью — отказ.
  Ctrl+Z → `undo_last()` возвращает всю запись разом. `purge()` очищает стек.
- Операции: `delete_group` (одна пара), `delete_batch` (выбранные, и режим «только превью без видео» — видео так удалить нельзя),
  `delete_folder` (папка со всем содержимым; не работает, пока идёт создание превью), `delete_empty` (пустые папки; перед переносом проверка заново).
- Пустая папка: нет файлов даже в подпапках; `Thumbs.db`, `desktop.ini`, `.DS_Store`, системные папки и корзина не в счёт; ссылки считаются файлами.
- Счётчик корзины (`TSTAT`) хранится в памяти, обновляется на ходу и пересчитывается обходом в фоне. **Не обходить корзину в обработчиках запросов:**
  по SMB тысяча файлов — десятки секунд, из-за этого уже зависало удаление.

## Создание превью (ffmpeg)

- Нужны `ffmpeg` и `ffprobe`. Поиск: `--ffmpeg` → рядом с программой (`base_dir()`, подпапки `ffmpeg`, `ffmpeg\bin`, `bin`) → PATH. Без ffmpeg страница показывает подсказку.
- Формат листа по образцу владельца: сетка 10×9, ширина 2560, кадры с линиями 1 px, на каждом кадре время `HH:MM:SS` в правом нижнем углу (drawtext на плашке).
  Заголовок с данными о файле — только с `--header`. Вертикальное видео — 18×5, короткое — меньше строк (по строке на каждые 10 с).
  Первый кадр на 00:00:00, дальше равномерно: `t_i = длительность * i / n`.
- Превью кладётся рядом с видео как `имя.jpg` (в режиме `--previews` — в ту же подпапку корня превью). Запись через `.part` и `os.replace`.
- **Кадры берутся пачками** (`extract_batch`): ~30 кадров за один запуск ffmpeg — несколько входов `-ss`/`-i` и `-filter_complex` с несколькими `-map`.
  Причина: запуск `ffmpeg.exe` в Windows стоит сотни миллисекунд, раньше было 92 запуска на видео. Если пачка не сработала, недостающие кадры
  этого видео берутся по одному (старый путь; ход — в строке «Now: имя (frames one by one: 32 of 90)», через `JOB['active']`). Быстрый режим
  отключается на сеанс, только если пачки не сработали у трёх видео **подряд** (`FAST['bad']` сбрасывается удачной пачкой): раньше
  хватало трёх сбоев за весь сеанс, и один битый файл (ошибка декодера на 2-часовой записи) замедлял всё. `--per-frame` — старый путь принудительно.
- Кадр берётся с ближайшего ключевого (`-noaccurate_seek`, быстро), метка — реальное время: `pts` + смещение перемотки
  (`%{pts\:gmtime\:<сек>\:%T}`). Пути в фильтрах — относительные от временной папки (cwd), шрифт копируется туда как `font.ttf`: так нет двоеточий и обратных слэшей.
- Шрифт подписи: Verdana (как DejaVu в образце) → Tahoma → Segoe UI → Arial; `--font` задаёт свой.
- Видеокарта: `--gpu on` включает `-hwaccel cuda`, по умолчанию процессор (для одного ключевого кадра NVDEC не быстрее: время уходит на запуск ffmpeg и чтение файла).
- Очередь: `start_job(ids, redo)` → `JQ['items']` (`[(id, redo)]`, под `JLOCK`) → потоки `worker` (`--jobs`, по умолчанию половина ядер,
  максимум 6) → прогресс в `JOB`, опрос страницей раз в секунду. **Пока очередь идёт, `start_job` дописывает в неё** (кроме уже стоящих и
  обрабатываемых; при нехватке потоков добавляет их; во время остановки — отказ), кнопка на странице — «Add to queue». Последний выходящий
  поток (`JQ['live']`) под той же блокировкой закрывает очередь и чистит временную папку — дописанное в этот момент не теряется.
  `stop_job()` убивает процессы ffmpeg; временная папка чистится всегда (в том числе по `atexit`). Битый файл не останавливает очередь, ошибка привязана к видео.
  Опрос страницы (`tickJob()`) не обрывается при сбое (раньше любая ошибка останавливала его, и списки «застывали»); списки
  перечитываются при каждом изменении `done`/`ok`.
- «Пересоздать»: старые превью переносятся в `_to_delete`, новое пишется на их место; при сбое записи старое возвращается.
  `make_preview()` возвращает `(новое превью, [(старое, куда перенесено)])`; `AFTER[gid]` — обработчик, который `worker` вызывает после успеха (им обрезка
  дописывает превью в свою запись отмены). Сетка листа считается в `sheet_grid()` — её же берёт обрезка.

## Обрезка видео (без перекодирования)

- Кнопка «Обрезать видео» (C) в просмотре → панель с таймлайном между картинкой и нижней панелью. Отмечается **удаляемое** (красное):
  протянуть мышью, края двигаются; I/O — начало/конец куска на курсоре; «Cut before/after cursor» — всё до/после курсора; Del — снять отметку
  с выбранного куска; K («Keep only this…», `keepOnlyStart()`) — сразу обрезка с одним подтверждением: остаётся только выбранный кусок
  (вырезаются `[0, a]` и `[b, d]`; общая часть с «Trim…» — `submitCut()`).
  Раскладка: слева действия (Reset, Keep only this, Trim…, Close), справа кнопки отметок. Пока открыта обрезка (`#v.cutting`),
  строка кнопок и управления просмотра `#vpl` и шкала `#vseek` скрыты — под панелью остаётся только имя видео. Клавиши в этом режиме перехватывает `cutKey()`
  (ничего не листается и не удаляется). Только для пар с одним видео; не во время создания превью и не во время другой обрезки.
- **Обрезка идёт в фоне и очередью**: после «Trim…»/K панель сразу закрывается; можно сразу обрезать следующее видео — оно встаёт в
  очередь `CUTQ` (`cut_start()`), нить `cut_loop()` режет по одной (`cut_one()`). Обрезка и создание превью не идут вместе: каждая обрезка
  ждёт, пока создание превью закончится (стадия «waiting for preview creation»), превью обрезанного пересоздаётся сразу
  (`start_job(..., internal=True)`), а внешний `start_job()`, пока очередь не пуста, отказывает. `CUT['running']` — очередь работает;
  `CUT['last']`/`seq` — итоги по одному (страница тостит каждый, `cutSeen`). `cut_stop()` без id — текущая и вся очередь (Stop в шапке),
  с id — только это видео (Stop/Cancel в `#vtrim` просмотра). Ход — в шапке (`#cutbar`, `renderCutBar()`, опрос `cutTick()`).
  Удаление видео (и его папки), которое только **ждёт** в очереди или текущая задача которого ещё на стадии «waiting for preview creation»,
  снимает задачу и удаляет (`trim_release()` в `delete_group`/`delete_batch`/`delete_folder`; снятая текущая — `CUT['stopped'] = 'deleted'`,
  итог с `silent`, страница его не тостит). Отказ (`trim_now()`, с именем видео) — только если оно режется/склеивается прямо сейчас:
  раньше отказ был и для ждущих, и владелец не понимал, почему «не обрезаемое» видео не удаляется. Отмену прошлой записи такого видео
  сервер по-прежнему не даёт (`trim_busy()`, `TRIM_BUSY` в `undo_last`); страница не играет его (`trimBusy(id)`) и не ставит в очередь второй раз.
- Всплывающий кадр над шкалой: сразу — клетка из листа превью (сетка от `cut_info()`, проверяется по размеру картинки; лист не узнан — клетки нет),
  через 0,2 с — точный кадр `GET /api/cut/frame/<id>?at=&w=` (ffmpeg, один запрос за раз).
- Только `-c copy`: оставляемый кусок может начинаться лишь с ключевого кадра. Начало каждого оставляемого куска сдвигается **назад** к ключевому кадру
  (`key_before()`: ffprobe `-read_intervals` вокруг точки, окна 8/40/240 с) — лишнее остаётся, нужное не теряется. На шкале эта часть полосатая.
- Сборка одним запуском ffmpeg: concat-список с `inpoint`/`outpoint`/`duration` (`-map 0:v:0 -map 0:a?`: субтитры и прочие потоки не переносятся).
  concat сравнивает `outpoint` с dts, поэтому `outpoint` уменьшен на задержку B-кадров (`bdelay` из `probe()`), а `duration` задан явно —
  иначе в кусок попадают лишние кадры, а на стыке время кадров совпадает. Проверено покадрово (framemd5) на x264 mp4 и mkv.
- Порядок: запись в `<видео>.part` → проверка длительности результата (допуск max(3 с, 2 %)) → оригинал в `_to_delete` → `os.replace` на его место →
  запись в `UNDO` → пересоздание превью через обычную очередь (`start_job`). Сбой/остановка до замены — оригинал не тронут, `.part` удаляется.
- `ff_call()` — свой запуск ffprobe/ffmpeg для обрезки: `run()` нельзя, он отказывает после остановки очереди превью (`STOP` остаётся взведённым).

## Объединение видео (без перекодирования)

- Выделить ≥ 2 плитки → «Merge (N)…» (`#smerge`, `openMerge()`) → `POST /api/merge/info {ids}` → просмотр в режиме склейки
  (`#v.cutting.merging`, состояние `M = {clips: [{id, info, cuts, snaps}], sel}`): та же панель `#cut`, над шкалой — `#mhead`
  (итог, ◀ Move / Move ▶, Remove from merge) и полоса роликов `#mstrip` (ширина — по длительности, красное — отметки).
  Клик по блоку — выбрать ролик (`mergeSelect()`: `C` строится на этот ролик, лист и шкала переключаются), перетаскивание — порядок
  (`mergeMove()`), Alt+←/→ — тоже порядок, PgUp/PgDn — соседний ролик. Отметки ролика — в его записи (`mergeSave()`: `normCuts` меняет массив).
  K в склейке только размечает. «Merge…» (`#mgo`, `startMerge()`) → `POST /api/merge/start {clips: [{id, cuts}]}`.
- Совместимость (`merge_probe()`): расширение, кодек и профиль видео, размер, `pix_fmt`, `r_frame_rate` (не `avg_frame_rate`: у переменной
  частоты он свой у каждого файла), `time_base` видео и звука (concat копирует пакеты как есть — при разной базе время второго ролика
  схлопывается, а проверка длительности с допуском 3 с это пропускает), кодек/частота/каналы звука и число звуковых дорожек.
  Имя результата не должно совпадать с парой или файлом с другим расширением (`a_merged.mkv` — та же пара). Сбой отката переноса
  исходников — оставшееся в корзине получает свою запись `UNDO`. При открытой обрезке/склейке Autoplay не запускает видео. Иначе отказ с перечнем, что отличается (решение владельца — только без перекодирования).
- Очередь общая с обрезкой: задачи `CUTQ` с `kind` `cut`/`merge` и `ids` (у склейки — все ролики); `trim_busy()`, `cut_stop(id)` и запреты
  удаления/отмены работают по любому из роликов. `merge_one()`: планы кусков — `keep_plan()` (общий с `cut_plan()`), строки concat — `concat_lines()`
  (общие с обрезкой), выход `<папка первого>/<имя первого>_merged<ext>` (занято — `_merged (2)`), `.part`, проверка длительности; потом все
  исходники и их превью → `_to_delete` (сбой — откат), `os.replace`, новая пара в `GROUPS`, превью — `start_job(internal=True)` + `AFTER`.
- Отмена: запись `[(новый id, MERGED, [], [(итог, корень)]), (id_i, группа_i, перенесённые_i)…]`; `undo_last()` уносит итог (и его превью)
  в корзину, убирает пару `MERGED` и возвращает исходники. Проверено через API и в браузере на синтетических x264 mp4 (стыки между файлами ровные).

## Просмотр и встроенный плеер (как в VO Media)

- Просмотр (`#v`) открывается **в окне** (полный экран — Enter или двойной клик) и **листом превью**: Enter/Space/клик в галерее
  только открывают его (`openViewer()`). Видео стартует само лишь с Autoplay A▶ (по умолчанию выкл., `auto`), с
  «Play here» в меню плитки (`openViewer(true)`; кнопок на плитке нет — подпись: имя слева, размер и дата справа), и следующим по окончании (▶|). Внешний плеер — только «Open in …» на листе и в меню (опции нет).
- Лист — это вид «видео не играет» (`pView(video)`, `P.vid`): лист при открытии, через 2 с паузы (`pPauseLater()`; кадр паузы виден эти 2 с
  и после перемотки на паузе), после Backspace (к началу) и в конце видео. Видео остаётся загруженным (`P.on`, `pLoaded()`), шкала и
  управление (`#vpl`, `#vseek`) видны, пока оно загружено; кнопки действий `#vb` (Select, Open in…, Trim, Delete) — только у листа.
- Разметка: `#vstage` (лист `#vi`, видео `#vv`, `#vfail`, HUD `#vmsg` + Restart, ‹ › ✕), `#vpv` (кадр над шкалой), `#cut`, `#vpanelbar`
  (шкала `#vseek`, строка `#vrow`: имя, позиция; под ней одна строка `#vpl` — сетка из трёх колонок: слева действия `#vb`, по центру
  ▶/скорость/время `#vplc`, справа звук и переключатели `#vplr`; ход обрезки `#vtrim`). `#vbar` — полоска создания
  превью в шапке, не панель просмотра. В окне панель всегда отдельной строкой под картинкой (и у листа, и у видео). Поверх видео — только
  в полном экране (`#v.playing.fs`): после старта воспроизведения прячется через 1 с (`barShow()`, классы `idle` и `nocur`) и не
  появляется до паузы или выхода из полного экрана; движение мыши показывает только курсор на 1 с (`curShow()`). Раньше mousemove
  показывал панель, а окно присылает его и без движения руки — панель мигала. I — `body.nobar`. Полосы кадров (T) и клавиши P нет — убраны по решению владельца.
- Клавиши — `viewerKey(e)`: Space и одиночный клик (через 250 мс) — играть/пауза (`pPlayPause()`), Enter и двойной клик — полный экран,
  Esc — видео на экране: пауза и лист, лист: закрыть; `\` — закрыть; ←/→: видео играет — перемотка 5 с, на паузе и на листе —
  соседнее видео (за краем — соседняя папка, `vGo`/`vCross`); Shift/Ctrl+←/→ — 30 с / 2 мин (решение владельца); Home/End, ↑↓ громкость, M, `,` `.` — кадр, Shift+`,` `.` — скорость, Backspace — к началу и лист,
  Del — удалить (всегда), E, `[` `]` PgUp PgDn, I. C и X в просмотре нет: обрезка и выделение — кнопками на листе. Колесо — соседнее
  превью, правый клик — меню плитки. Выход из полноэкранного режима браузера просмотр не закрывает.
- Перемотка зажатой клавишей копится в `P.seekT`, последнюю цель отправляет `seeked` (иначе каждая перемотка обрывает прошлую — грабли VO Media).
- Над шкалой — сразу клетка листа превью (`sheetLayout()`/`paintTile()`, общие с обрезкой; сетка — один `/api/cut/info` на видео; лист не
  узнан — клетки нет), через 150 мс — точный кадр со второго скрытого `<video>` (`pvCreate`/`pvRun`).
- Продолжение с места: `POST /api/progress {id, pos, dur}` раз в 10 с и при уходе с видео (если смотрели > 10 с); сервер хранит в
  `<app_dir>/positions.json` по пути видео с size/mtime (≤ 20 000, запись с задержкой 3 с и при выходе), `listing()` отдаёт `pos`/`dur`
  (после обрезки запись не подходит). На плитке — полоска «досмотрено» (`.wb`). «Resumed at …» + Restart.
- Предзагрузка: в режиме видео следующее с видео — `POST /api/prefetch {id}`; сервер держит 2 МБ начала и 1 МБ конца до 8 файлов (`Prefetch`),
  `Handler.video()` отдаёт кусок из памяти, если size/mtime совпали.
- Громкость, звук, скорость, Autoplay, Next, Loop — в настройках папки (`vol`, `mute`, `rate`, `auto`, `next`, `loop`).
- Не играет (ошибка `<video>` или нет `loadeddata` за 10 с: avi, wmv, ts, HEVC/AC3…) — окно «can't be played here» с кнопкой внешнего плеера.
- Сервер: `GET /v/<id>` (`Handler.video()`), Range по `parse_range()`, MIME из `VIDEO_TYPES`. Файл **открывается на каждый кусок** (`VIDEO_CHUNK`, 2 МБ)
  и сразу закрывается: `<video>` держит соединение, пока буфер полон, а открытый файл в Windows не дал бы удалить/обрезать видео.
  Сменился mtime посреди ответа (обрезка) — соединение рвётся. Страница отпускает файл (`pRelease()`) перед удалением, обрезкой и при листании.

## Обновление с GitHub и донаты

- `VERSION` — версия программы; тег релиза должен быть `v` + `VERSION` (сборка релиза это проверяет и падает при расхождении). Перед новым релизом поднять `VERSION`.
- Проверка: `check_update()` — `api.github.com/repos/<REPO>/releases/latest` (urllib, без ключа), один раз за запуск в фоне (по первому `GET /api/app`)
  и по кнопке в меню. Есть новее — зелёная точка на кнопке меню (☰) и пункт «Update to vX.Y».
- Вид установки — `install_kind()`: `exe` (Windows), `app` (macOS, `VO_SP.app`), `appimage` (Linux, переменная `APPIMAGE`), `source` (pairview.py),
  `''` — собрано как-то иначе, самообновления нет (страница предлагает скачать вручную). Файл релиза под каждый вид — `ASSETS`. С v1.5 файлы называются `VO_SP*`: версии до v1.4 (VSPO) ищут `VSPO*` и сами не обновятся — только вручную (решение владельца).
- Установка (`update_worker`): скачать файл релиза (проверка размера, сигнатуры `MZ`/`PK`/ELF, sha256 из поля `digest`, если GitHub его дал).
  exe — запущенный exe переименовать в `VO_SP.exe.old` (перезаписать его в Windows нельзя, переименовать можно) → новый на его место.
  app — `install_app()`: `ditto -x -k` во временную папку рядом с .app (ditto сохраняет права и ссылки), старое приложение → `VO_SP.app.old`, новое на место;
  скачанное нами не помечается карантином, Gatekeeper обновление не останавливает. AppImage и pairview.py (скачивается с тега, проверка `compile`) —
  `os.replace` поверх (в Linux/macOS запущенный файл так заменить можно). Потом `restart()`: тот же набор параметров, у собранных —
  `PYINSTALLER_RESET_ENVIRONMENT=1` и без `_MEI*`/`_PYI*`/`APPIMAGE*` в окружении; затем `os._exit(0)`.
  `.old` удаляет следующий запуск (`cleanup_old`). Нельзя во время создания превью и обрезки.
- Внешние ссылки — только по имени из `LINKS` (`POST /api/link {name}`), открываются браузером по умолчанию: в окне pywebview `<a target=_blank>` ненадёжен.
- Донаты: кнопка «Support» в шапке и пункт меню → окно с Monobank, Ko-fi, NOWPayments и QR (SVG банки Monobank, встроен в `PAGE`).
  Напоминание при запуске: раз в неделю, после «Remind me less often» — раз в месяц (`DONATE_DAYS`); о частоте в интерфейсе не писать.
  Первый запуск только назначает срок. Состояние — `donate: {next, rare}` в settings.json (общее, не по папке). На GitHub — `.github/FUNDING.yml`.

## Окно и интерфейс

- `main()` поднимает сервер в потоке и вызывает `run_window()` (pywebview, на Windows принудительно `gui='edgechromium'`: IE-движок страницу не потянет).
  Нет pywebview/WebView2/дисплея → запасной вариант: браузер. `--browser` — всегда браузер, `--no-browser` — только сервер.
- Полный экран просмотра (Enter, двойной клик): в окне pywebview — `window.pywebview.api.set_fullscreen` (окно целиком), в браузере —
  Fullscreen API. Esc в HTML-полноэкранном режиме перехватывает браузер: он только выходит из полного экрана, просмотр остаётся.
- Вкладки «Превью» и «Видео без превью» (список по папкам с галочками, исключённые папки запоминаются, создание превью, прогресс в шапке).
- Дерево папок слева — как в VO Media: сворачивается (`openDirs`, `topen` в настройках), строка «N · размер», шапка `#tsh` с сортировкой
  Name / Date / Size / Count и направлением (`tsort`, `tdesc`; Date — самая новая `mtime` в папке). Числа и сортировка следуют вкладке и
  «include subfolders» (`counts()`, `buildTree()`). Под шапкой — только «include subfolders» и «Empty folders…»; действия папки — в её
  контекстном меню (`folderPlay`, `folderExplorer`, `folderDelete`). Крошки пути `#crumbs` — последней строкой шапки (проводник — только в меню папки).
- Порядок дерева (`treeOrder()`) задаёт переходы: PgUp/PgDn и листание за край — `neighbor()`/`crossFolder()`, `[` `]` — соседи того же
  уровня (`siblingFolder()`), Backspace/Alt+↑ — `parentFolder()`.
- Клавиатура: общий обработчик keydown разбирает окна и F5, дальше `viewerKey` (просмотр), `treeKey` (дерево, `zone === 'tree'` после клика
  по строке: ↑↓, ←→, Home/End, Del — удалить папку, Esc/Enter/Tab — обратно), `gridKey` (галерея).
- Выделение плиток: чекбокс, Ctrl+клик, Shift+клик (диапазон), X, Ctrl+A. Панель действий над выбранными: удалить пары, пересоздать превью, играть во внешнем плеере.
- Сортировка галереи — как в VO Media: Name / Date / Size + направление (`srt`, `sdesc`; прежние `new`/`old`/`big` переводятся при загрузке).
- Свои диалоги `ask()` вместо системного `confirm()` (в окне приложения системные диалоги не гарантированы).
- Тема только тёмная; цвета — переменные в `:root` (акцент — градиент иконки `#7c5cff → #1e9bff`). Меню (☰) справа в шапке: обновление,
  поддержка, список горячих клавиш (окно `#keyp`; в шапке подсказок по клавишам больше нет — при новых клавишах дописывать туда), страница на GitHub, версия.
  Окна меню — `.sheet` внутри `#ov`, `sheet(id)`/`closeSheet()`; Esc закрывает.
- Открытая папка меняется без перезапуска: кнопка «Папка: имя ▾» в шапке → список недавних (до 10, `recent` в settings.json) или диалог
  (в своём окне — `create_file_dialog` pywebview, в браузере — tkinter). Путь с клиента принимается только из списка недавних, новый — только диалогом
  на стороне сервера. `switch_root()`: нельзя во время создания превью; `UNDO` очищается; номера пар продолжаются (картинки `/p/<id>` кешируются);
  счётчик корзины пересчитывается (у `TSTAT` поколение `gen`: устаревший обход не затирает новый). Страница после смены перезагружается
  (настройки у каждой папки свои; отложенная запись настроек отправляется до смены — `store.flush()`).
- Настройки интерфейса (порядок, размер плиток, подпапки, дерево, панель, исключённые папки) хранит **сервер**, по папке, в `%APPDATA%\pairview\settings.json`
  и подставляет в страницу (`const SETTINGS = /*SETTINGS*/{};`). Не `localStorage`: порт и окно меняются.

Горячие клавиши (лента): стрелки, Home/End — выбор; Enter/Space — просмотр (лист, видео не стартует без Autoplay); E — показать файл
в проводнике; Del — удалить пару (или все выбранные); Backspace/Alt+↑ — родительская папка; `[` `]` — папка того же уровня; PgUp PgDn —
соседняя папка с видео по дереву; X, Ctrl+A — выделение; Esc — снять выделение; Ctrl+Z — отменить; F5/Ctrl+R — обновить список.
Дерево (после клика по папке): ↑↓, ←→, Home/End, Del — удалить папку, Esc — в галерею. Просмотр и плеер — в разделе выше.
В обрезке: ←/→ курсор на 1 с (Shift — 10 с, Ctrl — минута), Home/End, I/O — начало/конец куска, K — сразу обрезать, оставив выбранный кусок,
Del — снять отметку с куска, Esc — снять отметку/выделение/закрыть.

Контекстное меню (правый клик, `#ctx`, `ctxShow()`): плитка и превью в просмотре — Play here, Play in <плеер>, дописать в плейлист (MPC), показать в проводнике, копировать путь/файл,
пересоздать превью, удалить; если плитка в выделении — действия над всем выделением; строка «без превью» — открыть, показать, копировать, создать превью;
папка в дереве — становится выбранной: Play in <плеер> (N), Add to playlist, проводник, Copy path, Delete folder… (Del). Копирование — `POST /api/copy` → `copy_paths()`: в Windows сервер кладёт
в буфер текст (`CF_UNICODETEXT`) или файлы (`CF_HDROP`, как «Копировать» в проводнике); в macOS/Linux путь возвращается и страница пишет его
`navigator.clipboard`, «Copy file» скрыт.

## Видеоплеер и проводник

- Плеер выбирается в меню (☰ → Video player): окно `#plp` со списком `list_players()`
  (Windows: MPC-HC/BE, VLC, PotPlayer, mpv; macOS: IINA/VLC/mpv в Applications и mpv из PATH; Linux: mpv, vlc, celluloid, smplayer, haruna, mpc-qt),
  «программа системы» (путь `''`) и «Choose another program…» (`ask_file()`, диалог на стороне сервера). Путь с клиента принимается только из этого списка.
- `PLAYER = {path, name, kind}`; `kind == 'mpc'` только у MPC-HC/BE в Windows. Выбор хранится в settings.json (`player`, общий) и важнее `--player`;
  не выбирали → `--player` → `auto_player()` (в Windows — MPC, иначе первый найденный, иначе программа системы).
- `play(files, add)`: MPC → `send_to_mpc()` (ниже). Остальные — **только воспроизведение**: один файл — путем, несколько — плейлистом
  `playlist.m3u8` в папке настроек (никаких ограничений длины командной строки); «Add to playlist» и вывод окна вперёд — только MPC
  (кнопка «Add to … playlist» скрыта). macOS: `.app` запускается через `open -a`. Enter/«Open video» тоже идут через `play()`.
- Показ в папке: Windows — `explorer /select,`; macOS — `open -R` (Finder с выделенным файлом); Linux — `xdg-open` папки. Подписи кнопок — по ОС (`osLabels()`).
- `find_player()`: `--player` → `MPC_DEFAULT` (путь K-Lite выше) → стандартные папки → PATH. Подходит и MPC-BE.
- `send_to_mpc(files, add)`: без `/add` — как «Play with MPC-HC» в проводнике (плейлист заменяется, воспроизведение сразу);
  с `/add` — дописывает в конец и **не** запускает воспроизведение. Файлы передаются списком (не папкой): не попадают игнорируемые `.ts`, порядок как в галерее.
  Командная строка Windows ограничена 32 767 знаками — длинный список режется на вызовы по ~24 000 знаков (первый — без `/add` при воспроизведении).
- Вывод окна вперёд (`bring_to_front` → `raise_window`): **без эмуляции клавиш**. Раньше «нажимался» Alt, и MPC входил в режим меню (странное поведение до Esc).
  Сейчас: AttachThreadInput + SetForegroundWindow → SwitchToThisWindow → на миг TOPMOST/NOTOPMOST. Окно ищется по имени файла/папки в заголовке,
  для MPC без имени в заголовке — по классу окна.

## HTTP API

Только `127.0.0.1`. Каждый запрос: ключ `?t=<токен>` (создаётся при старте) и проверка заголовка `Host` (только `127.0.0.1:<порт>` или `localhost:<порт>`); без них 403 `{"error": "access denied"}`.
Тело POST читается всегда (иначе при keep-alive оно «слипается» со следующим запросом). Ошибки — JSON `{"error": "..."}` с кодом.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | страница (с подставленными настройками) |
| GET | `/api/list` | пары-превью, видео без превью, undo, корзина, ffmpeg, job, mpc, ign, opts |
| GET | `/api/trash`, `/api/make` | счётчик корзины; статус создания превью |
| GET | `/p/<id>` | картинка превью (читается целиком и файл сразу закрывается) |
| GET | `/v/<id>` | видео пары для встроенного плеера (Range; файл открывается на каждый кусок; начало/конец — из предзагрузки) |
| POST | `/api/progress`, `/api/prefetch` | `{id, pos, dur}` — позиция просмотра; `{id}` — предзагрузить начало и конец видео |
| POST | `/api/delete/<id>`, `/api/delete-many`, `/api/undo` | удаление пары, выбранных, отмена |
| POST | `/api/open/<id>`, `/api/explorer`, `/api/mpc` | открыть видео в плеере, проводник, играть/дописать в плейлист (`play()`) |
| POST | `/api/copy` | `{ids}` или `{dir}`, `files` — путь/файлы в буфер обмена (`copy_paths()`) |
| GET/POST | `/api/player`, `/api/player/set`, `/api/player/pick` | список плееров; выбрать из списка (`{id}`); указать программу диалогом |
| POST | `/api/make`, `/api/make/stop` | создать/пересоздать превью (`{ids, redo}`), остановить |
| POST | `/api/rescan`, `/api/orphans` | обновить список; убрать превью без видео |
| POST | `/api/folder/info`, `/api/folder/delete`, `/api/empty`, `/api/empty/delete` | удаление папок |
| POST | `/api/purge`, `/api/trash/open`, `/api/settings` | начать очистку корзины в фоне, открыть её, сохранить настройки |
| GET | `/api/purge` | ход и итог очистки (`running`, `total`, `removed`, `bytes`, `failed`, `first`, `seq`) |
| POST | `/api/root/pick`, `/api/root/recent` | открыть другую папку: диалогом / из недавних (`{folder}`) |
| GET | `/api/app`, `/api/update` | версия, статус обновления и «пора напомнить о донатах» (один раз, срок сразу переносится); статус обновления |
| POST | `/api/update/check`, `/api/update/start`, `/api/donate/rare`, `/api/link` | проверить; скачать и перезапуститься; напоминать реже; открыть ссылку из `LINKS` |
| GET | `/api/cut`, `/api/cut/frame/<id>?at=&w=` | статус обрезки (текущая, `queue`, итоги `last`/`seq`); точный кадр (JPEG) |
| POST | `/api/cut/info`, `/api/cut/key`, `/api/cut/start`, `/api/cut/stop` | данные для шкалы; ключевой кадр не позже `at`; поставить в очередь (`{id, cuts: [[a, b]…]}`); остановить всё (`{}`) или одно видео (`{id}`) |
| POST | `/api/merge/info`, `/api/merge/start` | проверка совместимости и данные роликов (`{ids}`); склейка в очередь (`{clips: [{id, cuts}]}`, порядок = порядок склейки) |

Сервер (`Server`): в Windows порт занимается монопольно (`SO_EXCLUSIVEADDRUSE`, `allow_reuse_address=False`). Иначе второй экземпляр на том же порту
молча перехватывал запросы окна первого и отвечал «нет доступа». Порт по умолчанию — свободный (`--port 0`).

## Запуск и параметры

```
python pairview.py "D:\Видео"          # своё окно, если установлен pywebview, иначе браузер
pythonw.exe pairview.py "D:\Видео"     # без консоли (ярлык): журнал в %APPDATA%\pairview\pairview.log, ошибки запуска — окном сообщения
```

Постоянные параметры можно записать в `pairview.json` рядом с программой (`base_dir()`) или в `%APPDATA%\pairview`: ключи как у параметров без дефисов
(`{"folder": "D:\\Видео", "player": "...", "ignore_ext": "ts"}`). Командная строка важнее файла.
Папка без командной строки: папка прошлого запуска (`last_folder`/`last_previews` в settings.json) → `folder` из pairview.json → диалог (tkinter).
Пустая папка при запуске не завершает программу (кроме `--clean`): можно выбрать другую из шапки.

| Параметр | Смысл |
|---|---|
| `folder` | папка с видео (и превью, если лежат вместе) |
| `--previews` | отдельная папка с превью (подпапки те же) |
| `--clean videos\|previews [--apply]` | показать или перенести видео без превью / превью без видео (без окна) |
| `--purge` | удалить насовсем всё из `_to_delete` (с подтверждением) |
| `--ffmpeg`, `--font` | путь к ffmpeg (файл или папка), шрифт `.ttf` для подписей |
| `--player` | видеоплеер, пока не выбран в меню (`mpc-hc64.exe`, `vlc`, `mpv`, `.app` на macOS…) |
| `--cols 10 --rows 9 --width 2560 --header` | вид листа превью |
| `--gpu auto\|on\|off`, `--jobs N`, `--per-frame` | декодирование, число одновременных видео, кадры по одному |
| `--ignore-ext ts` | расширения видео, которые игнорировать (пусто — ничего) |
| `--port N`, `--browser`, `--no-browser` | порт, браузер вместо окна, только сервер |

## Сборка (PyInstaller, GitHub Actions)

Сборку делает GitHub Actions (`.github/workflows/build.yml`, workflow «Build»): при каждом push (и вручную — Run workflow) три задачи с Python 3.12:
`windows-latest` → `VO_SP.exe` (onefile), `macos-latest` (arm64) → `VO_SP.app` в `VO_SP-mac.zip` (ditto), `ubuntu-22.04` → onedir без pywebview,
упакованный appimagetool в `VO_SP-x86_64.AppImage` (WebKitGTK в AppImage не упаковывается: AppImage открывает браузер). Артефакты `VO_SP-windows`,
`VO_SP-macos`, `VO_SP-linux`. Тег `v*` или ручной запуск с тегом в поле release → задача `release` сверяет тег с `VERSION` и выкладывает все три файла.
macOS-приложение не подписано Apple: первый запуск — правый клик → Open или `xattr -cr`. Особенности собранных версий: `base_dir()` — рядом с .app /
.AppImage; `fix_env()` — Homebrew в PATH на macOS, исходный `LD_LIBRARY_PATH` для дочерних процессов в Linux; `die()` на macOS — `osascript`.
Вручную на Windows:

```
pip install pyinstaller pywebview
pyinstaller --onefile --noconsole --name VO_SP --icon assets/vo_sp.ico --collect-all webview --collect-all pythonnet --collect-all clr_loader pairview.py
```

- Результат — один файл `dist\VO_SP.exe`. Копировать нужно только его. `build\`, `dist\` и `VO_SP.spec` — временные, можно удалять (результат в `dist`).
- Без `--onefile` получится папка `dist\VO_SP\` (быстрее запускается, антивирус ругается реже); копировать её надо целиком.
- Python лучше 3.12: у `pythonnet` (нужен pywebview в Windows) бывают задержки с поддержкой самых новых версий.
- После любой правки кода exe нужно пересобрать (Actions делают это сами при push).
- ffmpeg в exe **не входит**: `ffmpeg.exe` и `ffprobe.exe` кладутся рядом с exe, либо в PATH, либо путь в `--ffmpeg`/`pairview.json`.
- `pairview.json` ищется рядом с exe (`base_dir()` — папка самого exe; в onefile `__file__` указывает во временную папку, поэтому берётся `sys.executable`).
- `--noconsole`: `sys.stdout` пуст, `setup_log()` пишет в `%APPDATA%\pairview\pairview.log`; фатальные ошибки показывает `die()` окном сообщения.
- Для своего окна нужен WebView2 (есть в Windows 11 и в большинстве Windows 10). Не вышло — программа сама откроется в браузере (причина в журнале).
- Сборка на Windows ни разу не проверялась автором этих правок: при ошибке сначала смотреть вывод PyInstaller и журнал.

## Грабли (не повторять)

1. `shutil.move` вместо `os.rename` → тихое копирование гигабайт и мусор в корзине.
2. Обход `_to_delete` на каждый запрос → десятки секунд по SMB (тысячи файлов `.ts` в корзине).
3. `SO_REUSEADDR` в Windows → два экземпляра на одном порту, окно получает «нет доступа».
4. Эмуляция Alt для вывода окна вперёд → MPC входит в режим меню.
5. Запуск `ffmpeg.exe` на каждый кадр → в Windows дико долго (поэтому пачки).
6. Двоеточия и обратные слэши в путях внутри фильтров ffmpeg → ломают фильтр: пути относительные, текст шапки через `textfile`.
7. `localStorage` для настроек → теряются при смене порта/окна: настройки на сервере.
8. Системное `confirm()` в окне pywebview → не гарантировано: свои диалоги `ask()`.
9. Перенос папки/файла, занятого плеером или рекордером стрима, в Windows невозможен: показывать понятную ошибку («файл занят…»), а не молчать.
10. Тройные кавычки внутри `PAGE` (это `r"""..."""`): нельзя в HTML/JS; плейсхолдер `/*SETTINGS*/{}` должен остаться как есть.
11. `run()` для разовых вызовов ffmpeg вне очереди превью → после «Остановить» всё падает с `Cancelled`: для таких вызовов `ff_call()`.
12. concat с `-c copy` без поправки `outpoint` на B-кадры и без `duration` → лишние кадры в конце куска и совпадающее время кадров на стыке.
13. Путь длиннее 260 знаков в Windows без `\\?\` (если длинные пути в системе не включены) → `FileNotFoundError`, глубокие папки молча пропадают.
    Все вызовы ОС к файлам библиотеки — через `lp()` (обход дерева — `lp(d, tree=True)`); в `GROUPS`, ответах и для ffmpeg/плеера — обычный путь.
14. `HTTPServer.server_bind` зовёт `getfqdn()` → медленный старт в Windows: `Server.server_bind` вызывает `TCPServer.server_bind` напрямую.
15. Имя файла с одиночным суррогатом (бывает с NAS) роняло весь `/api/list` при `encode('utf-8')`: такие имена `walk()` пропускает (`encodable()`).

## Что не проверено на настоящем Windows

pywebview/WebView2 и полноэкранный режим окна; вывод окна плеера вперёд; поведение `/add` и запуска в MPC владельца; NVDEC (`--gpu on`);
скорость создания превью с NAS по SMB и работа режима пачек кадров; самообновление exe, .app и AppImage (из исходников проверено в Linux); сборки и запуск на macOS и Linux;
выбор плеера (проверен в Linux с подставным mpv через API и в браузере);  диалог выбора папки из окна pywebview
(`create_file_dialog` из потока HTTP; при сбое — tkinter). Смена папки через список недавних проверена через API и в браузере.
Обрезка проверена на машине владельца с ffmpeg 8.1 на синтетических x264 mp4/mkv (API, покадрово, отмена, остановка; интерфейс — в браузере событиями из JS),
но не проверена: на настоящих записях стримов и HEVC, по SMB с NAS (скорость `key_before`/кадров), мышью в окне pywebview.
Правки до этого (выделение плиток, групповое удаление, удаление папок, счётчик корзины) проверены только на синтаксис.
Фоновая обрезка, «Keep only this», запреты удаления во время обрезки, `/api/copy` (буфер проверен `Get-Clipboard`), контекстное меню, Host с портом
и длинные пути проверены на машине владельца через API и во встроенном браузере; но в системе включён `LongPathsEnabled`, так что путь
без `lp()` там тоже работал бы — поведение на Windows с выключенными длинными путями не проверено. Правый клик в окне pywebview не проверен.
Встроенный плеер проверен во встроенном браузере (Chromium) на синтетических mp4/mkv (играют) и avi (окно «can't be played»), Range — через API,
удаление играющего видео в Windows проходит; не проверены: WebView2 в окне pywebview, записи стримов и HEVC, скорость по SMB с NAS.

Перенос из VO Media (дерево, клавиши, просмотр и плеер, позиции, предзагрузка) и очередь обрезки проверены во встроенном браузере (Chromium)
на синтетических mp4/mkv и через API (очередь из нескольких видео, отказ удалить ждущее, отмена из очереди, K, Ctrl+Z после обрезок);
не проверены: окно pywebview/WebView2 (полный экран, автоскрытие панели), мышь в нём, скорость по SMB с NAS, длинные записи стримов и HEVC.

## Как проверять правки

```
python -m py_compile pairview.py
node -e "const s=require('fs').readFileSync('pairview.py','utf8'); new Function(s.split('<script>')[1].split('</script>')[0]); console.log('JS OK')"
```

Автотестов в проекте нет и заводить их не нужно. Работа ведётся прямо на Windows-машине владельца: при разрешении можно поднять сервер
на временных папках (`PAIRVIEW_HOME=<временная папка>` — чтобы не трогать настоящие настройки; `--no-browser --port N`) и дёрнуть API.
Остальное — вручную на машине владельца. Интерфейс и сообщения — по-английски; не переименовывать `pairview.py`.
